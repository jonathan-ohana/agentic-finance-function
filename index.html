An agentic finance function, run end to end

Bookkeeping, month-end close, variance analysis, board reporting and reforecast — operated by AI agents under a governance layer that keeps every number traceable and every judgment on record.

Built and pressure-tested in a simulated B2B SaaS environment, working from standard system exports rather than custom integrations.

agent, first run charter v1.0

Four contract expiry dates were computed, then reported as though read from the document, then escalated as contradictions — against documents that did not contradict themselves. Not an arithmetic error. A provenance error.

human ruling RL-0024

Every extracted value carries its basis. Read requires a quote. Derived requires the derivation. A computed value may never be reported as an observed one.

agent, later run charter v1.1

Same four contracts, re-extracted blind by two independent agents, with a control and a genuine contradiction included as checks. All four read correctly. Zero false escalations. The real contradiction was still raised — and the agent gave its reason:

“Escalating this as a contradiction would repeat review ledger RL-0024, where four contracts were wrongly flagged on computed expiry dates.”

Whythe question

Attribution is solved. Causality isn’t.

AI-native finance tools tell you what moved — which account, which entity, which entries. They cannot tell you why in business terms, because the why isn’t in the ledger. Seeing the story through the noise is still the finance professional’s job.

So the question was never whether agents can close the books. It was: what layer captures a finance professional’s judgment and compounds it, so the function gets smarter each month instead of re-deciding the same things?

Evidencefour claims

  • Every number traces to a versioned definition, with human rulings on contested items definitions · rulings

  • Corrections persist — each close is smarter than the last loop verification
Failuresthree, unedited

What broke

  • The agent silently improved the plan

    Mid-run, the Analyst re-derived two plan lines on a better basis than the one on file — and flipped the sign on a variance. The improvement was correct; the behaviour was wrong. Plan values are read, never recomputed. Now blocked by a hash check that stops the pack rendering. Read the incident

  • Judgment collapsed into template-filling

    Given three permitted ways to end a variance comment, the agent picked the computable one every time — “reforecast candidate” stamped on 10 of 17 comments, owner questions extinct. Contract satisfied, judgment lost. The ending is now set by the playbook, not chosen by the agent.

  • A derived value reported as an observed one

    The provenance error above, which became RL-0024. The review session

Shapethree layers

Buy the ledger. Build the judgment.

Judgment layer

Semantic layer and rulings · playbooks and exemplars · output contracts · correction ledger · adversarial review

Agents

Bookkeeper · Analyst · Reporter · Forecaster · Controller · Evidence · Chief of Staff

Source systems

GL · billing · CRM · payroll · bank — exports only, no custom integrations

The judgment layer is made of decisions no vendor can ship, and it is the only layer here meant to outlive the tools underneath it. Autonomy is earned per workflow, never per agent, with a documented demotion trigger for each.

Limitsstated plainly

What this is not

  • One simulated company. A second instance was built to test portability, and nothing more.
  • One operator. Self-graded.
  • No real company’s books have been through this.
  • The learning loop is a demonstrated mechanism, not a track record. One correction, one rule, one later run that cited it. That distinction is kept throughout.
  • Calibration — thresholds, voice, account-specific rules — is company-specific and does not transfer. The machinery does.
